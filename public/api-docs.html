Documentație API RA Tracks

API REST pentru integrarea datelor de monitorizare GPS și flotă în sistemele tale (ERP, TMS, BI). Răspunsuri JSON, autentificare cu cheie API, plus webhooks pentru evenimente în timp real.

Base URLhttps://ratrack.ro/api
FormatJSON (UTF-8). Corpurile de cerere: Content-Type: application/json.
AutentificareCheie API (header Authorization: Bearer sau X-API-Key)
Fus orarTimestamp-urile sunt ISO 8601 UTC (ex. 2026-06-18T07:30:00.000Z)
Cuprins: Autentificare · Poziții live · Vehicule · Istoric · Rapoarte · Management · Webhooks. Derulează pagina sau folosește căutarea browserului (Ctrl+F).

Autentificare

Accesul se face cu o cheie API (prefix gpsk_) generată de administratorul contului tău din Administrare → Chei API. Cheia este legată de un utilizator și moștenește automat rolul și accesul acelui utilizator la vehicule — deci „vede" exact aceeași flotă pe care o vede acel cont în aplicație.

Trimite cheia pe fiecare cerere, în unul din cele două anteturi:

Authorization: Bearer gpsk_xxxxxxxxxxxxxxxxxxxxxxxx
# sau
X-API-Key: gpsk_xxxxxxxxxxxxxxxxxxxxxxxx

Exemplu complet:

curl -H "Authorization: Bearer gpsk_xxxx" https://ratrack.ro/api/live
Securitate: cheia se afișează o singură dată la creare (stocăm doar hash-ul). Tratează-o ca pe o parolă — nu o pune în cod public/front-end. Poate fi revocată oricând din panou. Toate apelurile trebuie făcute prin HTTPS.
Domeniu de acces: o cheie nu poate accesa date din altă companie și nici vehicule în afara accesului contului ei. Dacă vrei acces read-only, leagă cheia de un cont cu rol „Vizualizare".

Convenții & limite

SubiectDetaliu
Rate limit~1200 cereri/minut per cheie (20/min pe endpoint-urile AI). La depășire: 429 + antet Retry-After (secunde).
Istoric/api/history acceptă o fereastră de maxim 92 de zile per cerere (altfel 400).
Filtrare vehiculeParametrul imei acceptă mai multe IMEI-uri separate prin virgulă (acolo unde e suportat).
ScriereEndpoint-urile POST/PUT/DELETE funcționează doar dacă rolul cheii permite (administrare flotă). Cheile read-only primesc 403.

Coduri de eroare

Erorile întorc un JSON { "error": "mesaj" } cu unul din statusurile:

CodSemnificație
400Cerere invalidă (parametri lipsă/greșiți, interval prea mare).
401Cheie lipsă, invalidă sau expirată.
402Abonament expirat — acces suspendat (contactează furnizorul).
403Acces interzis (rol insuficient sau resursă din altă companie/vehicul fără acces).
404Resursă inexistentă.
429Prea multe cereri (rate limit).
500/503Eroare/serviciu indisponibil temporar.

Poziții live

GET/api/live

Cea mai recentă poziție a fiecărui vehicul din flota accesibilă (în memorie, actualizat în timp real). Vehiculele arhivate nu apar.

[
  {
    "imei": "860123456789012",
    "name": "Logan Alb",
    "plate": "B 123 ABC",
    "vehicle_type": "Auto",
    "latitude": 44.4325,
    "longitude": 26.1039,
    "speed": 54,                // km/h
    "angle": 187,               // grade (0 = nord)
    "satellites": 11,
    "timestamp": "2026-06-18T07:30:12.000Z",
    "io": {
      "ignition": 1,            // 1 = contact pornit
      "external_voltage": 13800,// mV
      "gsm_signal": 4,          // 0–5
      "can_total_mileage": 145200,     // km (odometru CAN)
      "can_fuel_level_liters": 48,
      "can_engine_temp": 86,           // °C
      "can_engine_rpm": 1450
      // ... alte câmpuri CAN/IO disponibile pe vehicul
    }
  }
]
Recomandare de polling: la 10–15 secunde. Pentru flux în timp real fără polling, folosește Webhooks.

Istoric traseu

GET/api/history/{imei}

Pozițiile istorice ale unui vehicul într-un interval. Parametri: from, to (ISO 8601). Implicit: ultimele 24h. Maxim 92 zile/cerere. Adaugă ?ext=1 pentru câmpuri extinse + sumar depășiri de viteză.

curl -H "Authorization: Bearer gpsk_xxxx" \
  "https://ratrack.ro/api/history/860123456789012?from=2026-06-17T00:00:00Z&to=2026-06-18T00:00:00Z"
[
  { "timestamp": "2026-06-17T06:01:00.000Z", "latitude": 44.43, "longitude": 26.10,
    "altitude": 82, "angle": 187, "speed": 0, "satellites": 10, "io_data": { ... } }
]

Rapoarte

GET/api/reports

Lista tipurilor de rapoarte disponibile (19 tipuri, 5 categorii: monitorizare, consum, CAN, evenimente, siguranță/EcoDrive).

{ "categories": [ { "key": "monitorizare", "label": "Monitorizare" }, ... ],

Generează un raport. Parametri: from, to, imei (opțional; mai multe separate cu virgulă — implicit toată flota), și format=pdf sau format=xlsx pentru export fișier (altfel JSON).

curl -H "Authorization: Bearer gpsk_xxxx" \
  "https://ratrack.ro/api/reports/trips?from=2026-06-01T00:00:00Z&to=2026-06-18T00:00:00Z"

# Excel
curl -H "Authorization: Bearer gpsk_xxxx" -o raport.xlsx \
  "https://ratrack.ro/api/reports/trips?from=...&to=...&format=xlsx"

Webhooks (evenimente push)

În loc să interoghezi periodic API-ul, poți primi evenimentele împinse automat către o adresă din sistemul tău (ERP/TMS). La fiecare eveniment, trimitem un POST JSON semnat HMAC.

Configurare

GET/api/webhooks
POST/api/webhooks rol administrator
DELETE/api/webhooks/{id}
POST/api/webhooks/{id}/test
POST /api/webhooks
{ "url": "https://erp.firma.ro/hooks/ratracks",
  "events": ["overspeed", "fuel_drop"] }   // gol/absent = toate evenimentele

// Răspuns — secretul de semnătură se afișează O SINGURĂ DATĂ:
{ "id": 1, "url": "...", "events": [...], "secret": "whsec_xxxxxxxx" }

Configurarea se poate face și din aplicație: Meniu → Administrare → Webhooks (integrări) (listă, adăugare, buton „Testează", status livrare).

Evenimente disponibile

overspeedfuel_dropidling engine_tempoverloadlow_voltage no_ignition_movedtc_errortest

Forma payload-ului

POST  (către URL-ul tău)
Content-Type: application/json
X-RaTracks-Signature: sha256=<hmac_hex>

{
  "company_id": 12,
  "ts": "2026-06-18T07:31:00.000Z",
  "event": "overspeed",
  "imei": "860123456789012",
  "vehicle": "Logan Alb",
  "severity": "warning",
  "message": "Viteză 96 km/h",
  "value": 96
}
Livrare: timeout 5s, fără reîncercare imediată; un eveniment nu se repetă mai des de 2 minute per vehicul. Răspunde cu 2xx ca să confirmi primirea. Statusul ultimei livrări e vizibil în lista de webhooks.

Verificarea semnăturii (HMAC SHA-256)

Fiecare livrare include antetul X-RaTracks-Signature: sha256=<hex>, unde hex = HMAC-SHA256 al corpului brut al cererii, cu secretul webhook-ului. Verifică-l înainte de a procesa evenimentul.

Node.js (Express)

const crypto = require('crypto');
app.post('/hooks/ratracks', express.raw({ type: 'application/json' }), (req, res) => {
  const sig = req.header('X-RaTracks-Signature') || '';
  const expected = 'sha256=' + crypto.createHmac('sha256', WEBHOOK_SECRET)
                                      .update(req.body).digest('hex');
  const ok = sig.length === expected.length &&
             crypto.timingSafeEqual(Buffer.from(sig), Buffer.from(expected));
  if (!ok) return res.status(401).end();
  const event = JSON.parse(req.body.toString());
  // ... procesează event ...
  res.json({ ok: true });
});

PHP

$body = file_get_contents('php://input');
$sig  = $_SERVER['HTTP_X_RATRACKS_SIGNATURE'] ?? '';
$expected = 'sha256=' . hash_hmac('sha256', $body, $WEBHOOK_SECRET);
if (!hash_equals($expected, $sig)) { http_response_code(401); exit; }
$event = json_decode($body, true);

Python (Flask)

import hmac, hashlib
sig = request.headers.get('X-RaTracks-Signature', '')
expected = 'sha256=' + hmac.new(SECRET.encode(), request.data, hashlib.sha256).hexdigest()
if not hmac.compare_digest(sig, expected):
    abort(401)
event = request.get_json()

Bune practici

  • Stochează cheia API în siguranță (variabile de mediu / secret manager), nu în front-end.
  • Polling pentru poziții la 10–15s; pentru evenimente folosește webhooks (mai eficient, în timp real).
  • Respectă rate limit-ul; la 429 așteaptă conform antetului Retry-After.
  • Pentru rapoarte mari, limitează intervalul (max 92 zile la istoric) și folosește export xlsx/pdf.
  • Verifică întotdeauna semnătura HMAC a webhook-urilor.
  • Tratează câmpurile io ca opționale — variază în funcție de hardware/CAN-ul fiecărui vehicul.
